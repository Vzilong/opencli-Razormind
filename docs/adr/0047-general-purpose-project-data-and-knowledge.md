# 通用项目数据与知识能力，业务分类由场景模板提供

日期：2026-09-14

状态：通用知识库阶段已实现并通过集成验收；独立 Dataset 实体及成果导航拆分仍为后续设计。本阶段取代 ADR-0046 中品牌作为知识必选归属的部分，保留其来源、版本、权限与人工发布规则。

## 问题证据

- `frontend/lib/navigation.ts` 将“品牌知识库”“品牌与产品”作为默认一级业务入口。
- `frontend/app/(app)/knowledge/page.tsx` 要求工作区和品牌同时选中才打开知识库。
- `backend/models/brand_knowledge.py` 的 `KnowledgePage.brand_id` 是必选归属；项目通过 `BrandProjectScope` 间接关联知识。
- 数据页复用 `BrandScopeFields`，按当前品牌/产品分类过滤，而不是以项目和数据集为通用入口。

这使技术调研、项目文档问答等用户必须先构造无意义的品牌。仅改菜单文案会掩盖约束，不能满足产品要求。

## 产品边界

平台负责获取信息、保留原始来源、规范化数据、生成带证据的成果，并向下游 Agent 提供授权查询和显式执行工具。
核心概念不依赖用户所属行业。首发仍集中于公开研究、变化监测、项目知识查询三个场景，不扩张成任意业务系统搭建器。

## 默认导航

| 入口 | 用户任务 | 默认筛选 |
| --- | --- | --- |
| 项目 | 定义目标、选择模板、配置来源和下游接入 | 工作区 |
| 数据集 | 浏览采集及规范化记录、结构和来源 | 工作区、项目、数据集 |
| 知识库 | 导入资料、整理草稿、审核发布、检索版本 | 工作区、知识库；项目可选 |
| 任务与成果 | 查看运行状态、报告、变化摘要、引用和缺口 | 工作区、项目、任务 |

“运行与数据”可以保留为导航分组名称。“品牌与产品”不再是默认导航或创建知识的前置步骤。
字段详情允许行业字段存在，但默认列表以标题、来源、采集时间、状态和版本等通用信息组织。

## 归属与授权

- **Workspace** 是成员、权限、可复用来源和知识资源的归属边界。
- **Project** 是工作目标、任务执行及下游 Agent 查询的范围，沿用现有 Studio Project，避免再造另一套项目。
- **Dataset** 组织结构化记录，归属于明确项目；保留原有任务、工作流、来源和版本血缘。
- **KnowledgeLibrary** 是工作区内的知识容器，包含目录、原始资料、整理页和版本。创建时不要求品牌或其他业务对象。
- **ProjectKnowledgeBinding** 明确授予项目使用哪些知识库或限定子集。同处一个工作区不代表下游项目可以查询全部知识。
- **Run / Artifact** 记录任务及成果，继续区分原始采集证据、模型结论、未完成缺口和变化证据。

知识库可以被多个项目显式引用；它不是第二套项目。禁止通过“未绑定品牌”回退成全工作区搜索。
查询保持只读，采集、分析、监测由单独执行操作启动。

## 业务分类的位置

模板可以提供“研究对象”及可选字段、分组和视图。例如：

| 场景模板 | 示例对象/字段 | 使用的通用能力 |
| --- | --- | --- |
| 公开研究 | 主题、问题、参考链接 | 来源、知识库、研究任务、引用报告 |
| 竞品变化监测 | 公司、品牌、产品、监测页面 | 数据集、来源基线、变化任务、差异成果 |
| 项目知识查询 | 软件仓库、模块、文档类型 | 知识库、项目绑定、版本和检索 |

用户可以直接创建空白项目。品牌/产品功能保留为可选模板能力，不能通过空白模板路径重新成为隐含必填项。
首发使用少量模板配置和现有记录元数据，暂不引入任意实体设计器、通用关系图谱或新的插件市场。

## 兼容迁移要求

1. 增加知识库及项目绑定的通用归属，不直接删除或重命名旧品牌表。
2. 每个已有品牌知识空间映射到同工作区的一个知识库；产品分类及其原有可见范围完整保留。绝不能将原来只授权一个产品的项目扩权到整个知识库。
3. 保留资料 ID、原始文件、哈希、版本、引用和旧项目关联。迁移以幂等映射和数量/权限对账验证，具备回退路径。
4. 新入口及 API 使用通用知识库/项目范围；旧 `/brands` 与品牌路径在兼容期继续可访问并指向对应资源，不静默丢弃请求中的分类约束。
5. 原记录保留执行血缘；没有项目血缘的旧数据保持原授权规则并明确展示迁移状态，不为凑齐结构虚构归属，也不扩大可见范围。
6. 下游 API/MCP 保持现有项目身份校验与查询契约，底层知识检索改为显式库绑定。旧客户端继续可用。

## 验收门槛

- 全新安装无需创建任何品牌，即可完成项目创建、资料导入、知识发布和授权查询。
- 上述三个模板共用同一核心数据/知识能力，行业字段不进入通用必填字段。
- 创建空白项目后不出现强制品牌/产品步骤。
- 项目 A 未绑定的库不会出现在其 REST、MCP 或聊天工具结果中；跨工作区访问仍拒绝。
- 从旧品牌/产品结构迁移后，数量、原始文件哈希、历史版本、引用与原有产品可见范围逐项相符。
- 用户可在真实界面将资料从来源追溯到成果，并由下游 Agent 查询；测试不得仅通过修改标题来宣称通用化完成。

## 实施状态

当前执行范围为通用知识库、显式项目绑定、兼容迁移、记录的通用项目筛选和下游权限整合；独立 Dataset 实体及成果导航拆分尚未实施。
