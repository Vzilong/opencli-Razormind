# OpenCLI-Razormind 产品定位与首发场景

> 产品设计草案。场景优先级和首发用户属于待验证假设；本文不代表模板已实现或已发布。

**为你的 Agent 准备好可查询、可引用、可更新的数据。**

OpenCLI-Razormind 是可自托管的信息获取与分析上游。平台内置工具和 Agent，负责搜索、采集、清洗、分析与维护来源证据；Codex、Claude Code 等下游 Agent 通过 API / MCP 查询成果，或调用平台工具补充资料。平台持有采集配置、凭证和项目数据，下游使用被授权的数据与任务接口。

## 首发用户与问题

[ASSUMPTION] 首发面向已经使用编程 Agent 的独立开发者和小团队。他们需要为技术选择、产品研究和实现任务获取最新资料，却反复进行搜索、复制网页、整理上下文；后续难以知道材料何时更新、结论引用了什么。

用户已经确认的边界是：平台 Agent 服务于本平台的数据处理，下游 Agent 消费成果或调用工具；开源首发需要少量明确场景和模板。首发用户选择、使用频率和愿意维护自托管服务的程度尚未经用户研究验证。

## 已有基础与当前差距

仓库已有采集、Records、工作流、知识检索和 `/mcp` 接口。聊天 Agent 的工具列表尚缺直接搜索与网页读取；现有场景卡片不能证明各场景闭环已跑通。首发工作应收束这些存量能力并补齐场景缺口，按任务交付验收，不以增加工具数为完成标准。

## 三个应用场景，一条共同的数据链

| 首发顺序 | 应用场景与模板 | 用户提供 | 平台交付 | 下游接着做什么 |
| --- | --- | --- | --- | --- |
| 1：主打入口 | 公开资料研究 / research-brief | 一个问题，可选参考链接 | 带引用的研究简报、结构化发现、证据与缺口 | Codex 据此做技术选型或实现方案 |
| 2：持续使用 | 竞品变化跟踪 / competitor-watch | 少量产品官网、发布日志或 RSS | 相对上次成功采集的变化、来源快照、变化摘要 | Claude Code 据此更新对比文档或需求建议 |
| 3：复用成果 | 项目知识供给 / project-context | 授权的项目资料、文档链接或已有成果 | 可检索资料、版本和来源明确的回答上下文 | 下游按当前任务取用材料，生成文档或实现功能 |

共同链路：来源 → 采集记录 / 快照 → 清洗 → 分析与引用 → 项目成果 → API / MCP。研究模板找到的资料可成为项目知识；跟踪模板更新已有资料。三者共用存储、身份授权和工具服务。

模板须具备可配置的输入、可运行的定义、演示材料、结果示例、下游调用示例和验收条件。详细设计见 [场景模板与首发体验](addendum.md)。

## 首次体验

入口只突出「做一次研究」「跟踪变化」「连接项目知识」三个任务。用户选模板、填写少量业务输入、检查必要配置、执行并查看成果；画布作为高级编辑入口。主页先展示结果示例和来源，再解释工具与工作流。

演示模式用于无凭证浏览预置样例，显著标记为演示，不能计作实时采集成功。真实模式先检查来源和模型配置；未配置则给出具体缺项。公开网页 / RSS 优先，登录站点采集作为可选增强。

## 首发范围与非目标

首发提供一次真实研究的端到端体验；其他模板通过验收后逐个开放。已有行业模板、浏览器管理、多机资源、模型设置继续保留，收纳到高级或行业入口；不迁移或删除用户项目。暂不将开放包市场、通用多 Agent 编排和多行业整套方案纳入首发承诺。

## 发布门槛

发布门槛：用户在新安装环境中按公开说明完成配置后，能以真实模式运行一个模板，追溯每项关键结论的证据，并通过一个实际下游客户端查询同一次运行的成果。查询已有成果不重复调用分析模型；新任务返回任务标识和实际执行状态。系统对越权访问、来源失败、资料过期和无结果分别给出明确提示。

## 采用验证

[ASSUMPTION] 体验目标：安装完成后 5 分钟内看懂演示成果；来源和模型配置完成后 15 分钟内完成一次限定规模的真实研究。这是待测试目标，不是运行时间保证。耗时数据按安装、配置和执行三个阶段分别记录，不合并计算。

开源采用验证关注「新用户是否独立完成首个真实运行」「能否从下游成功查询」「7 天内是否再次使用或更新资料」。这些指标通过自愿测试反馈和本地诊断收集；不默认上传用户问题、内容或遥测。先观察小规模试用，不能由功能数量推断采用率。
