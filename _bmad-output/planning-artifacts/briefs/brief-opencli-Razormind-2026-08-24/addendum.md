# 场景模板与首发体验

本文是 [产品简报](brief.md) 的配套设计。下面的模板 ID、输入输出字段和下游任务示例均为拟议契约，不是已注册工具或可导入工作流。落地时必须映射到后端现有注册表、数据模型和权限；运行定义通过真实执行验收后才能标记可用。

## 所有模板共同交付的内容

| 组成 | 要求 |
| --- | --- |
| 模板身份 | 稳定 ID、版本、适用任务、具体输入、输出结构 |
| 执行定义 | 绑定已注册能力和版本；通过编译不等于通过真实运行 |
| 配置检查 | 区分缺模型、缺搜索服务、来源不可达、登录失效和无权限 |
| 示例材料 | 自行编写或许可明确；显著标记演示，不伪造最新事实 |
| 结果展示 | 先显示成果、来源、时间与完整性，再允许查看 Trace |
| 下游接入 | API 和 MCP 文档、实例地址、凭证配置说明、可复制任务提示词 |
| 验证证据 | 演示结果、真实运行结果、下游读取、失败用例分别验证 |

### 统一成果契约

统一成果至少带项目标识、成果版本、运行标识、完成时间、来源引用与完整性。具体字段名称与现有 Records / Run / Evidence 模型对齐，不为每个模板新建一套平台对象。

### 统一任务契约

对外分为「查询已有成果」「检索来源片段」「发起新采集或分析」「查询任务状态」。已有 MCP 的 `list_records`、`trigger_task`、`get_task` 可作为基础，但不能把未来分析任务契约写成现已支持。耗时任务应返回任务 ID；完成、局部失败、失败和无结果应能区分，不能统一标记为成功。

### 统一权限契约

平台聊天、工作流、API 和 MCP 共用能力服务。凭证作用域、查询授权和任务权限应在共享服务入口校验；现有 API token 或可选过滤参数不等于已完成项目级授权。查询与运行分权，查询已有成果不触发隐式重采集或分析。

## 模板 1：公开资料研究

### 用户任务

**用户任务：**「帮我研究如何为一个小型 SaaS 增加全文搜索，把最新官方资料整理给我的编程 Agent。」

### 输入与约束

输入只要求研究问题；高级选项提供参考 URL、允许的域名、时间范围和来源上限。默认手动执行，最多读取 5 个来源，不自动扩大任务。实时搜索需可用搜索服务；分析需配置模型。当仅有网页读取能力可用时，可运行「指定资料研究」，并明确表示未执行全网搜索。

### 输入契约示例

```json
{
  "template_id": "research-brief",
  "question": "比较两个候选全文搜索方案，关注部署要求、中文支持和官方限制",
  "seed_urls": [],
  "max_sources": 5,
  "delivery": "project_results"
}
```

### 流程与交付

流程：拆解问题 → 搜索 → 选择和读取正文 → 去重并保存来源 → 对比证据 → 形成简报与结构化发现。每条关键发现绑定记录或快照 ID、原始链接和获取时间。正文是资料，不可作为改变平台工具权限的指令。

交付包含 `findings`（发现与引用）、`sources`（来源及状态）、`gaps`（未回答问题）、`limitations`（限制）及可读报告。来源发布时间未知时留空，不能用抓取时间冒充发布时间。相互矛盾的资料并列呈现；搜索摘要不等于读过正文。

### 下游调用

下游示例提示词：「查询项目最新研究成果，先列出引用和未解决问题，再根据发现给出实现方案。」执行方案由下游负责。

### 演示

演示材料：自行编写的两个虚构软件说明页，一页包含部署限制，一页包含中文能力及未知项；预置结果标记演示。真实验收改用用户授权的公开来源。

### 验收

验收：真实模式搜索与正文读取均有运行记录；至少两个不同来源支持比较，且引用可回到内容片段。单一来源或部分失败允许输出局部结果，但状态为不完整，不声称完成交叉验证。无来源时返回无证据，不生成肯定研究结论。下游能查询到与平台页面相同的成果版本。

## 模板 2：竞品变化跟踪

### 用户任务

**用户任务：**「跟踪三个竞品的产品页和更新日志，告诉我新增了什么，并让我的 Agent 更新对比文档。」

### 输入与约束

输入为对象名称和公开页面 / RSS；首发上限 3 个对象、共 6 个来源。初次手动运行建立基线；持续跟踪由用户显式启用调度。默认建议每日一次；抓取频率受站点和平台限制。仅比较用户配置的对象，不自动扩展到全网舆情。

### 输入契约示例

```json
{
  "template_id": "competitor-watch",
  "targets": [
    {"name": "示例产品 A", "urls": ["https://product-a.example/changelog"]}
  ],
  "schedule_enabled": false,
  "suggested_cadence": "daily",
  "delivery": "project_results"
}
```

`.example` 地址仅用于说明输入格式，不可作为真实运行来源。

### 流程与交付

流程：读取来源 → 提取主要正文 → 保存快照 → 对比上次成功快照 → 识别新增 / 修改 / 删除片段 → 生成有证据的变化摘要。分析模型不可仅凭两段摘要推断页面变更。

交付包含 `baseline_run_id`、`current_run_id`、`changes`、`unchanged_sources`、`failed_sources`。每项变化同时引用前后快照；首次运行状态为已建立基线，不把整个页面记为新增事件。

### 下游调用

下游示例提示词：「查询竞品项目自上次运行以来的变化，引用前后证据，生成对比文档的更新建议。」平台不代替下游写入其仓库。

### 演示

演示材料：同一虚构产品的前后两份页面，仅修改一个功能段落，并加入变化的页脚时间。预期只出现有业务意义的功能变化。

### 验收

验收：相同内容重复运行不产生重复事件；无变化明确显示无变化；抓取失败不覆盖成功基线，不算内容删除；单来源失败保留其失败状态。启用调度后需真实验证再次运行。外部通知单独配置，未配置不能声称已发送。

## 模板 3：项目知识供给

### 用户任务

**用户任务：**「把产品说明、接口文档和已有研究整理成资料库，让 Codex 每次实现前先查我们的资料。」

### 输入与约束

输入必须绑定到调用者已获服务端授权的项目；用户可选择已有成果、上传文本资料或指定文档 URL。首发单批最多 10 份文本 / Markdown / 网页资料，文件大小和 URL 访问遵循现有后端限制。PDF、多媒体和登录站点等格式仅在对应解析能力验收后开放。默认只查询；更新资料是显式操作。

### 输入契约示例

```json
{
  "template_id": "project-context",
  "source_mode": "existing_project_results",
  "max_documents": 10,
  "delivery": "queryable_project_knowledge"
}
```

### 流程与交付

流程：读取授权资料 → 记录来源和版本 → 分段与索引 → 按问题检索 → 返回片段和引用。先复用现有检索机制，不把新增向量数据库作为首发前提。品牌 / 产品知识已有独立作用域，项目与知识资料的绑定需要显式映射和授权校验，不能从全库搜索后再过滤。

交付包含 `query`、`matches`（片段、来源 ID、版本、更新时间）、`gaps`。检索结果可直接交给下游；平台生成回答属于可选分析，不能让每次取用资料都必须付出模型调用成本。旧版本可追溯，当前查询默认使用有效版本。

### 下游调用

下游示例提示词：「先检索当前项目关于接口鉴权的资料，列出版本与引用，再按资料实现客户端；资料缺失时说明，不推测配置。」

### 演示

演示材料：虚构项目的接口说明、术语表和一份变更记录；提供三个有答案的问题和一个没有答案的问题。

### 验收

验收：命中片段能回到具体资料版本；未知问题返回未找到；更新后能检索到新内容；删除或撤销访问后不能继续从缓存或索引取到内容。其他项目或未授权调用不能读到资料。平台页面和下游查询的版本一致。

## 新用户路径与开源展示

第一屏文案建议：「为你的 Agent 准备好数据。搜索、采集和分析公开资料，用 API / MCP 交给 Codex、Claude Code。」

三个入口分别展示一个成果样例。新用户先看演示，再填写研究问题并配置必要依赖，运行后看到发现、证据和缺口，最后从「连接你的 Agent」复制当前实例的接入说明。高级工作流编辑和行业模板放到后续入口。

开源首页首发只主推研究场景：一段短演示覆盖提问、真实取数、查看来源、下游消费。搭配最小安装说明、明确依赖与成本归属、一个可复现样例和 API / MCP 示例。竞品跟踪和知识供给逐个验收后再标为可用。

提供 Codex、Claude Code 各一份接入说明，并分别做真实客户端验证；只跑通一个客户端时只承诺该客户端。离线演示不作为协议或网络联调通过的证据。首发不默认开启遥测，也不以星标数代替用户完成任务的证据。

## 存量能力映射与范围控制

| 已检查的入口 | 可复用内容 | 首发仍需证明 |
| --- | --- | --- |
| `backend/api/v1/chat.py` | 平台工具调用循环、过程事件 | 搜索 / 正文读取接入及研究成果交付 |
| `backend/workflow/capability_projection.py` | SearXNG 预设及来源能力描述 | 配置后的真实可用性、Agent 可调用性 |
| `backend/mcp_server.py` | 记录查询、任务触发 / 状态、工作流工具 | 分析与知识契约、项目作用域、下游客户端联调 |
| `backend/api/v1/records.py` | 记录检索、项目等筛选 | 外部消费时不能省略的授权边界 |
| `backend/services/brand_knowledge_service.py` | 品牌 / 产品作用域检索与资料版本 | 项目绑定、下游访问与变更后的检索一致性 |
| `frontend/lib/workflow/studio-templates.ts` | 现有模板卡片与图构造 | 各模板业务执行语义；部分模板复用基础图，不能仅凭卡片判定完整 |

此表是代码阅读结果，不是运行验收报告。模板清理只调整首发推荐与信息层级，不删除现有用户数据、模板 ID 或工作流。行业专项、全站大规模抓取、开放包市场、复杂预测与多 Agent 编排暂不作为首发承诺。

## 外部设计参考与假设边界

本次沿用此前简报记录中的自托管、Deep Research、可信源数据链与 API / MCP 上游定位。历史页面争议、Issue 状态和当时的运行问题保留在过程记录中，不作为当前实现状态。当前场景定位进入简报，跨场景契约、验收与来源依据进入本附录。

[Firecrawl MCP 文档](https://docs.firecrawl.dev/use-cases/developers-mcp) 用单页抓取、站点链接发现等具体任务解释工具；[快速试跑示例](https://docs.firecrawl.dev/quickstarts/amp) 提供可直接交给 Agent 的任务提示词。[OpenBB MCP 文档](https://docs.openbb.co/odp/python/quickstart/mcp) 展示已有只读 API 经 MCP 暴露的路径。这些支持任务式入口和 API 复用的设计参考，不证明本项目会获得采用。

三个场景、默认规模和首发受众是设计假设。需要试用验证：用户能否独立配置真实来源、是否理解演示与真实结果、下游是否实际使用证据、后续是否复用或更新。业务需求进入实现阶段时按仓库约定记录在 GitHub Issues；本文保留产品设计，不承担任务状态追踪。
